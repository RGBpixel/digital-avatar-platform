# 摄像头接待试用
1. 正常启动项目，展示页展开“摄像头”。勾选同意仅本机处理，点击开启摄像头。
2. 选择自由交谈、内部建卡或来访建卡；要自动交谈再勾选“来人时主动问候并开始交谈”，允许麦克风。
3. 一人正对镜头，两次稳定检测后问候；短暂持续站着不反复问候，离开后重新进入，问候间隔至少30秒。多人暂停。
4. 建卡前本人同意照片登记可勾选；只登记文字也可以。点击开始所选模式建卡，逐项回答，选填项可说跳过，最后核对并明确确认保存。
5. 内部卡片待审核，设置页“内部审批”沿用模拟管理员确认；外来卡片不授予单位权限。
6. 再次出现可给出人脸候选；点击“本人/操作员确认候选”后，只有已授权个性化聊天才会读取偏好与确认记忆。不能凭候选执行审批。
7. 后台已有人员可从双目录选定后拍摄正脸；管理员先在后台建立文字卡片并配置模拟管理角色，再登记照片。可删除照片和模板而保留文字卡片。

模型来源及哈希见models/face-opencv/source.json，模型目录保留各自许可：
- https://github.com/opencv/opencv_zoo/tree/main/models/face_detection_yunet
- https://github.com/opencv/opencv_zoo/tree/main/models/face_recognition_sface
实际部署前需复核权重及训练来源许可；本轮仅本机原型验证。

后台预先建卡：设置页新增“后台人员建卡与管理”，可填写姓名/昵称/部门/生日月日/单位/岗位/兴趣，独立征得资料和个性化同意；可创建内部或来访卡片。首位模拟管理员可直接初始化，其后需模拟确认现有管理员，新增最多3位；取消管理员角色保留卡片，删除卡片同时清理照片模板、审批、权限及留言。未获审批的普通内部卡片仍待审核，不由自述或人脸自动授予。现阶段仍是本机无账号原型，不可公网部署。

人员档案照片上传：设置→人员档案，选择已有卡片后可上传JPG/PNG/WebP（<=8MB），浏览器缩放为JPEG预览；单独本人同意后调用原本机face-enroll检测单人正脸并保存。重启/切换选择读取已保存对齐头像，不需要开启摄像头；选人/场所改变清除上传草稿，失败不覆盖旧参照。

2026-10-15 识别纠正：实际发现内部文字卡片未关联照片，照片曾保存到旧测试卡片；经本人确认后将唯一参照转至目标卡片，保留文字档案及原权限状态。照片区域显示目标姓名、卡片ID短号，人员列表标记是否已登记人脸。区分登记质量（正脸>=90px）与回访检测质量（相同正脸几何约束且>=50px），匹配分数门槛0.45及候选差距0.08保持不变。前端显示登记人数和质量/相似度/歧义原因。参照自检不等于现场识别准确率验证。

对话身份衔接：主对话区显示当前人脸候选/本人确认状态；“我是谁/你认识我吗”等先由本机按真实检测状态说明，不发送给无身份上下文的云模型。连续两次候选一致后，明确说“我是[候选称呼]”或在身份核对提问后说“是的”可关联已授权聊天；无候选/候选变化不确认。确认不产生审批或设备权限。低置信度临时暂停私人记忆，不因单帧候选丢失直接取消正在回答；多人或连续无人仍结束旧会话。

实机继续修复：自动内部建卡只在连续5帧未知时启动，稳定现有候选会取消自动新建卡草稿；人工明确启动的建卡不被姓名确认规则抢占。身份确认支持已登记姓名及昵称（如姓名与日常称呼不同）。摄像头设备ID保存到启动偏好，避免插入新的USB摄像头后刷新默认切换黑屏设备。匹配门槛保持不变。


## 2026-10-16 接待体验调整
内部人员统一由后台系统录入与管理；停用摄像头员工交谈新建入口，后端拒绝内部建卡会话，已有人员资料保留。旧internal摄像头模式迁移到访客自然接待。访客自然接待一次问一项称呼/单位/拜访对象/预约/来意，不首次追问兴趣生日岗位。资料只留会话草稿；简短复核内容、期限并得到同意后保存，拒答/取消不存，不进行隐瞒式采集。兴趣可在熟悉后的普通交谈中提及，仍通过现有确认修改入口保存，尚未自动从普通聊天中抽取偏好。人脸单独授权不变；预约为自述、未核验，不自动发送通知或授予权限。已知人员走识别与问候，不重开访谈；连续8次无人后才重置来人状态，自动问候间隔至少120秒，短暂遮挡不重启采集。


### 内部同事问候优先
稳定内部候选先欢迎回来，待本人确认后继续，不把未确认候选送入访客问询。访客轻量问答中发现姓名对应内部记录或对方说明来上班，终止访客问卷但不按姓名授予身份。模型在已关联internal时使用内部同事问候，覆盖岗位默认拜访话术。


## 2026-10-16 人脸＋档案声纹联合确认（聊天试用）
后台人员档案新增本人声纹登记：人工核对目标卡片、取得本人同意后录制3–15秒，提取当前本机CAM++特征，原始录音不落盘，页面未保存录音最多暂存60秒。每人保留最多3份显式登记参考，保存于data/voice-identity.sqlite，随人员到期/删除清理，可单独删除声纹。与临时旁人过滤声纹区分，不将唤醒录音自动登记到档案。
单人稳定人脸候选有声纹登记时提示回应“你好宝贝，我来了”，本次录音先交本机进行联合核对。后端发放绑定场所与人选、10秒内一次性的核对挑战，并在声纹推理后复查最新人脸候选。声纹分数须达到0.72，且比其他已登记人员至少高0.05（试用参数，未经正式误识率标定）。模型/维度变化要求重新登记，失败不关联、不进入访客问卷，可继续重说或使用现有显式人工确认。联合通过后关联本人已授权聊天与待告知事项，再用当次录音锁定本轮收音以过滤旁人；不自动更新持久声纹。
当前人脸无活体防伪、声纹不能抵御录音重放，不作为门禁、管理员权限或安全身份认证。已实现与自动化测试完成；真实本人录音登记、现场误拒绝率/误接受率和重放防护未验收。


## 2026-10-16 当前接待识别策略：视频优先
按用户最新决定，改为摄像头视频流自动识别，不要求声纹登记、说姓名或点击确认。后端要求同一人连续至少3张不同JPEG画面、跨度至少1.2秒且每帧满足原人脸匹配门槛，才发放8秒内一次性接待关联凭据；重复静止图像不累计，不确定/多人/换人清空轨迹。前端自动关联已授权的聊天记忆与该人员留言，内部人员欢迎上班，不问拜访谁；语音提醒和继续收音沿用“来人主动交谈”开关。声纹登记保留备用，默认接待流程不启用。检测与关联、朗读分开执行，朗读时继续检测视频。仍为聊天接待原型，不声明活体防伪，不授予设备或管理权限。


## 2026-10-16 公共资讯池与天气
设置新增独立“公共资讯与天气”页面，按场所持久保存于data/public-info.sqlite。公司资讯/社会新闻分栏，人工添加标题、摘要、来源、发布时间、有效期和公开/仅内部范围；停用条目不会在后续RSS刷新时重新出现。自动社会新闻来自中新网公开RSS，仅最近72小时并保留出处；每30分钟缓存更新，启动时检查已开启场所，不在语音回复路径临时等待网络。公司资讯仍需工作人员提供，不虚构。天气接Open-Meteo城市级接口，用户选择稍后设城市，当前不预设或定位；缓存过2小时不使用，网络失败明确说明。
对话模型只接收当前有效资讯，内部条目仅在已关联的内部人员上下文中提供，不使用过期天气编造当前实况。视频识别本人后的主动开场可附一个资讯话题，个人未读留言/快递优先；同人3小时内不主动再讲新资讯，同条目7天内不重复；话题历史持久保存，人员到期或删除后访问时清理。自动选题只采用文化、科技等轻松标题与天气，当前是规则挑选，不宣称已实现AI兴趣推荐、全文新闻核验或个性化新闻总结。公开资讯源和模型提示均不执行网页中的指令，不向新闻/天气接口发送人员档案。
