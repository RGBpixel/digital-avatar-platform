# 内部固定人员与外部来访者

## 确认的两条工作线
所有真人按场所分为内部固定人员和外部来访者。内部岗位可为领导、员工、保洁等，岗位名称与设备权限分开；管理人员是独立授权角色，不由自述职务产生。外部人员允许昵称和自述快递员、修理工、物流等身份，不强制真实姓名，来访目的与历史交流作为经本人确认的资料。

内部：摄像头/交谈收集资料 → 本人确认草稿 → 内部待审核卡片 → 管理人员核对确认 → 固定人员目录 → 单独配置指定设备动作及时间有效期。最多3位管理人员用于本机模拟验证（实际人数可后续配置）。真实初始管理员需离线/可信后台核验，再单独授权；人脸匹配只能确认候选，不得从未知人脸、自称领导或模型答案授予管理员身份。生产管理员人脸确认必须接独立身份凭据与授权服务。

外部：未知人员问候 → 询问昵称、自述身份、来访目的和可选兴趣 → 明确同意保存 → 外部卡片；无单位权限。再次识别可信确认后，按本人同意范围读取称呼和相关旧记忆，先友好问候再延续话题；不确定时先问称呼，不展示他人上下文。照片、模板与档案分别管理，未同意人脸登记仍可临时服务。

## 当前已实现
Person加入affiliation=internal/external、selfRole、roleSource=self-reported。旧employee/customer/visitor/regular分类保留，归属不直接产生权限。既有档案读取时按旧类别补充缺省归属，不丢弃原资料。建档对话新增内部/外部与岗位/身份问答；内部确认保存后自动送入本机审批队列。卡片固定资料快照，资料变化后不能按旧卡批准，需驳回重提。同名用Person ID区分。
Organization按场所持久化data/organization.json：审批卡片、模拟管理员、审批通过目录、时间权限、内部留言和操作记录。模拟身份会话5分钟有效，权限规则按人员+door/light/ac+on/off+起止时间；开与关分别配置，截止时刻失效，可撤销。外部和未审核人员不能取得内部会话或设备权限。既有真实门禁路径仍拒绝；模拟权限接口返回realCommandSent:false，没有连接设备。
内部员工可以互相留言：发信人需当前审批内部模拟身份，接收人按内部ID选择；文本保存到本机收件箱，重复请求幂等，仅接收人查看/标记已读。展示页新增交谈留言：说接收人称呼、重名时确认序号、说明内容，再明确“确认发送”，才入收件箱；含糊回复/取消不发。飞书/钉钉未接入，保存不等于已外部送达，不是自动预约或日程提醒。
撤回删除档案时清理其审批卡、权限、管理角色及相关留言；过期访问触发关联清理。本机文件尚未加密，真实账户权限与数据治理未完成，不能部署公网。审批后台展示卡片供本机操作人员使用；生产版本必须用授权管理员上下文替代客户端site/token模拟入口。

## 简单体验步骤
1. 关闭旧启动窗口，重启启动项目.cmd或含声音模型入口，刷新网页。
2. 设置页登记初始管理人员：归属选内部，填写岗位，明确本人同意。进入“内部审批、设备权限与留言”，刷新，选此人，点击模拟初始化首位管理人员，再模拟确认。仅初始化首位，其他管理员由该人确认。
3. 开始陌生人接待，用交谈填写固定人员资料，在归属步骤回复内部。明确保存后刷新审批区，选待审核卡，核对快照，管理人员模拟确认。外部回复外部，身份可填快递员等；不会进入内部权限。
4. 管理人员可选审批通过的固定人员设管理角色（最多3人），配置门/灯/空调的单个开关动作和起止时间；以当前模拟人员测试，只返回模拟结果。
5. 模拟确认发信人员后，在设置写留言或展示页通过交谈留言；切换并模拟确认接收人，查看自己的收件箱，标记已读。

## 2026-10-16 每人信息告知栏
按场所与Person ID在data/person-messages.sqlite持久保存待告知事项，支持员工/访客互相转达、公司通知标签、快递/外卖放置说明。后台卡片下可查看并添加；展示页支持转达口头流程，未建档留言人可自述称呼，不强制建卡。重名收件人需选具体ID，明确核对后发送，重复请求幂等。摄像头候选只提示有待收信息；本人确认后创建独立5分钟留言会话，一批最多转达3条，提示不自动变已读，本人说知道了或点击确认后标记已读。每轮已提示项不重复自动朗读；剩余事项按批转达。当前确认是本机原型关联，非可信身份鉴权，不产生门禁或管理权限。后台无正式账号授权，生产化仍需账户隔离、活体确认与公开场所播报策略。自述姓名不代表已认证发件人；预约时间、明天等原文保留并附留言时间，不执行日程。过期、删档关联清理；旧内部留言按ID导入展示，原功能保留。无短信、飞书/钉钉发送。
