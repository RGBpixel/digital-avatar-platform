# 现场数字接待需求与验收草案

状态：已纳入项目目标；2026-10-12 完成基础模拟流程，真实设备与生产数据管理待实现。场景包括企业前台、餐厅和其他服务行业。

## 企业流程
1. 检测到来人，数字人问候；多人场景确认当前交谈对象。
2. 员工：经可信方式确认身份，按管理员配置的角色与权限提供服务；可留口信、接收快递提醒。模型不能给自己或用户授予权限。
3. 访客：询问称呼、拜访对象、目的和预约。称呼是访客自述，不等于已核实身份。
4. 明确说明记忆登记内容，获得同意后建立来访记录，可关联人脸模板、姓名/称呼和必要上下文。拒绝人脸登记仍可接待。
5. 按被访员工目录，通过配置的飞书或钉钉发送最少必要的到访通知，等待员工确认；禁止默认附带人脸图像或完整聊天。
6. 开门由独立权限服务决策，依据可信身份、门的范围、时段、访客确认及设备规则执行。对话请求或人脸相似度单独不能触发开门。保留操作记录与人工处理入口。

## 餐厅流程
支持老王、老张、Michael 等昵称，不要求真实姓名。得到同意后将昵称与人脸模板、熟客目录及偏好关联。
记录咸淡、辣度、喜欢/不喜欢的食物、配料种类和份量。记录来源和更新时间，区分明确偏好与系统推测；改变偏好先确认。
再次来访可以友好问候，匹配不确定时先询问称呼，不当众说出档案细节；不能因匹配错误把他人偏好用于下单。
过敏等信息如后续加入，应独立确认，不能从一般口味推断。点餐、支付和预订是后续独立业务接口。

## 记忆与数据模型
- Person：内部人员 ID、场所 ID、类别（员工/访客/熟客）、昵称和身份核实状态。
- FaceEnrollment：人员 ID、登记同意与用途、模板版本、有效状态；图像与模板分离管理，不默认永久保存原始录像。
- Visit：来访时间、拜访对象、来访目的、接待/确认状态。
- Memory：必要摘要、来源、确认状态、更新时间、保留期限；不默认保存全部对话。
- Preference：字段、值、单位/等级、确认来源与时间。
- Permission：员工/接待员/管理员等角色、允许操作、门禁范围、有效期。顾客或访客昵称不产生员工权限。
- Notification/AccessEvent：幂等键、关联来访、状态、回执、操作人/服务、审计记录。
不同企业/餐厅默认隔离，不创建跨场所通用人脸库。允许查阅、修正、删除、撤销登记和设置保留期限。员工个人设置不能覆盖企业授权规则。

## 设备与服务适配
CameraAdapter：检测事件、临时追踪 ID、时间、画面区域；断线状态与重新连接。追踪 ID 不是永久人员身份。
IdentityAdapter：登记、匹配候选、置信度、未知/不确定、独立身份确认。面对门禁需评估活体及其他验证措施。
AudioAdapter：独立麦克风/扬声器、回声消除与背景噪声处理；不假定摄像头自带可用双向音频。
MessagingAdapter：飞书/钉钉，按目录路由、最少信息、幂等、重试与回执。
AccessAdapter：只接收独立权限服务批准的指令；超时、拒绝、成功回执和人工处理。
海康威视为候选设备品牌，型号和接口待提供后核实。视频流、厂家检测事件、人脸能力、双向音频、门禁可能是不同接口与设备，不能合并假设。

## 对话风格
接待模式采用企业或餐厅设置的礼貌语气。幽默可选且强度可配置，不把剧场尖锐调侃默认应用于访客或员工。

## 交付和验证顺序
先以模拟设备开发人员目录、记忆与接待流程；再接实际摄像头；再联调经授权的消息；门禁最后单独验证。
覆盖误识别、照片冒用、同名、多人、遮挡、重复事件、设备离线、通知失败、员工未确认、登记撤回与跨场所越权。未经确认不得输出他人档案或执行开门。

## 模拟实现说明
企业和餐厅通过统一 Reception 服务落地，前端为本机操作人员控制台。当前无员工身份或角色授权实现、无自动身份匹配，不采集人脸。人员目录已改为 SQLite，重启保留；默认30天到期在访问档案或列表时清理。接待拒绝登记可建立无档案临时来访。门禁模拟始终拒绝；通知不会离开本机。

## 可配置现场服务
接待扩展为客户定义的服务岗位。企业、餐厅、展厅、景区、博物馆、家庭、培训机构、美容院使用统一场所配置与岗位配置；同模板多个场所保持独立人员目录。问候、知识范围、流程和转人工说明由客户调整，设备接口与权限继续独立管理。

## 当前画面接待切换（2026-10-27）
- 摄像头第一帧失去当前匹配时暂停使用旧人员聊天记忆；连续两次无人检测释放当前会话。
- 连续两次未知或不确定人脸检测后，结束旧身份并重新接待当前访客；新的已登记候选直接解除旧会话，重新连续核对。
- 换人清除旧聊天上下文、未完成草稿、待播报和口讯身份；新访客不继承上一位的两分钟问候冷却。不删除已保存档案或口讯。
- 旧身份的异步问候完成后不得重新开启监听；自动接待仍受界面开关控制。实际延迟取决于摄像头和人脸检测耗时，不保证固定秒数。
- 自动回归覆盖无人离开、陌生人接替、已知人员接替及单帧误检。真实摄像头换人验收待用户测试。
