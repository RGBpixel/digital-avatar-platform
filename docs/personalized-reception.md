# 认识真人并延续交流

## 已确认目标
摄像头检测真人 → 查询本场所自愿登记的人脸模板 → 产生身份候选 → 确认当前交谈对象 → 关联 Person ID → 查阅获准用于聊天的档案与相关记忆 → 数字人问候并自然延续交流 → 提议需要新增/纠正的记忆 → 本人确认后保存。

人物档案卡包括称呼、员工/顾客/访客类别、授权头像、兴趣偏好、标签、历史事件与已确认的交流摘要。档案主体是真人，与数字人形象分开。头像便于后台核对，人脸特征模板用于匹配，二者不是同一字段；头像照片不自动构成识别库。检测到陌生人不会凭空知道名字，先询问称呼；同名人员使用不同内部ID。

## 记忆接口与扩展模型
FaceEnrollment：personId、siteId、用途同意、头像对象ID、加密模板引用、模型版本、撤回状态。CameraAdapter只输出临时trackId；IdentityAdapter输出候选与未知/不确定状态；独立确认服务签发场所、人员、会话、短时有效的身份关联。真实确认不接受客户端verified:true。
ConversationSession：当前交谈对象、会话归属、短时确认和取消；多人或换人时重确认。ConversationTurn：可选保存的历史轮次，需独立告知保留范围；当前不保存完整聊天。MemoryItem：兴趣/偏好/事件/摘要、时间、来源、本人确认、共享范围、有效期。MemoryRetriever只取当前人员、当前场所、获准且与问题相关的少量记忆，不把全档案送给模型。私密事件默认不在公共接待区域提及，过时资料先询问。MemoryProposal只生成候选，禁止把推测或模型编造事件自动写成事实。删除与撤回需要覆盖头像、模板、聊天和关联记忆。员工分类不产生权限。

## 本轮已实现
Person加入personalizationConsent，默认关闭；本人明确确认并保存后才允许模拟会话使用资料。PersonalConversation为后台操作人员模拟身份关联，5分钟有效，返回verified:false与operator-simulated，不等于可信识别。读取前每次校验场所、有效期、档案存在及聊天授权；撤回/删除立即阻止再次读取。
POST /api/conversation-sessions?site=:id {personId,confirmed:true}；POST /api/chat?site=:id {text,sessionId}。无sessionId时不读取私人档案，伪造personId/verified不会关联。当前DialogueAdapter用固定模板引用称呼、已确认偏好、标签和摘要，明确标注模拟，不自动保存对话。选择他人、换场所或新的模拟摄像头事件会解除前端关联，停止旧播放并清空旧回答。

## 后续实现
授权头像上传/摄像头采集与后台档案卡；真实检测、人脸模板匹配及不确定身份确认；会话短期记忆与经确认历史事件列表；真实模型、相关记忆检索与摘要提议；公共环境隐私范围、账户/租户授权及生产数据治理。未获同意的陌生人可用匿名临时接待，不默认抓取并保存所有人的头像或历史。
