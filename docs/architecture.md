# 架构草案

共用后台管理会话、角色身份、人设、模型服务、语音与口播任务；客户端渲染通过适配器执行通用表演事件。
网页提供统一操作入口；轻量角色在本地显示。UE 处理高质量三维、小剧场及可选的离线渲染任务。
手机先验证响应式网页，后根据性能需要决定 App。UE 云端串流为可选方案，不默认让所有会话占用云 GPU。

角色身份可对应不同端资源：同一小熊猫可拥有二维和三维资产；资产转换与动作重定向不是自动完成。

实时事件至少包含会话、回答、角色、序号、时间、表演类型和参数。音频播放时钟驱动嘴型与动作。打断时按回答 ID 取消声音和表演。
口播任务保存稿件版本、声音设置、场景、资源版本、时间轴、任务状态和输出；最终视频由服务器统一合成以保证声音、字幕与画面一致。

第一阶段不引入 UE、数据库集群或微服务部署。先确定本机可运行的最小前后端，后续按需拆分。

## 第一阶段落地（2026-10-12）
Node.js 24 原生 HTTP 后台 + 无构建依赖的 HTML/CSS/JS 网页，绑定 127.0.0.1:3210。UI 是本机策划/开发控制台，尚无账户鉴权，不部署公网。
接待业务集中在 Reception，通过构造函数注入 MessagingAdapter 与 AccessAdapter；CameraAdapter、IdentityAdapter、DialogueAdapter 分离，可逐项替换。企业与餐厅共用来访流程，通过 site 隔离数据。当前允许的场所是 office 与 restaurant，后续由账户授权的场所上下文替代前端参数。
人员目录、偏好、标签和确认摘要存入本机 SQLite；来访仍为内存存储，重启清空，登记默认 30 天有效。新增适配协议见 contracts/service-adapters.md。真实长期记忆需持久化、账户权限、加密、删除/保留策略和备份验证。
模拟检测只生成临时 trackId，不匹配人员；UI 目录供本机操作人员演示，不作为面向访客的档案展示。身份和权限不可由对话或客户端设置。门禁请求阶段一全部拒绝，后续独立 PermissionService 完成可信身份、员工确认、门范围和时段校验，再调用设备适配器。
通知按来访 ID 幂等，并发复用同一请求；失败可手动重试。只传演示员工路由与必要目的，不传昵称、人脸、偏好或聊天。真实消息接入前需凭证、路由配置和明确启用。

## 场所与岗位配置扩展
Workspace = 独立场所 ID + 行业 templateId + 工作环境 + 岗位描述 + 问候语/语气 + 职责/知识范围 + 服务流程/人工接管说明 + revision。行业模板只用于初始化，不是人员隔离键。Reception 注入 WorkspaceStore 验证场所，所有档案与来访按场所 ID 隔离，切换模板不移动档案。
WorkspaceStore 串行写入 data/workspaces.json，以临时文件与重命名保存；更新使用 revision 防止覆盖其他编辑。数据目录不进 Git，场所配置重启保留，人员改用本机 SQLite，来访仍是内存演示。配置文件损坏不静默覆盖。
模型服务获取当前岗位配置；现阶段 DialogueAdapter 只演示 role 与 greeting 生效，职责、知识和流程仅保存，不伪装自动执行。后续增加检索知识库、版本化流程节点、语言/声音/动作映射和由独立授权服务控制的工具能力。
现阶段控制台仅本机无鉴权；客户自助上线前必须建立租户/管理员授权、发布审核与配置版本回滚，不能信任前端提供的场所 ID。

## 显示配置 DisplayProfile
前端保存 preset、width、height、shape(rectangle/circle)、framing(full/upper/head)，浏览器恢复配置并校验宽高和圆形比例。画布通过 aspect-ratio、宽度上限及遮罩预览；角色使用 SVG 等比取景，头部模式只渲染头部，半身使用上半身边界，不变形。
当前 DisplayProfile 为浏览器级展示偏好，不与场所岗位或权限合并，不改变物理设备。后续统一传给网页、UE 相机适配与视频合成；每种正式资产提供身体边界、头部锚点、安全边距，按客户端能力执行。

## 语音与讲解状态
客户端 VoiceConfig 按场所ID与角色ID保存 source、voiceURI/sampleId、personality、emotion、intensity、rate、autoNarrate。声音身份不等于人格；人格可影响后续模型表达，情绪由声音/动作适配器按能力执行。当前对话仍为模拟。
本机声音通过 speechSynthesis.getVoices 只列 localService=true 的声音，播放与停止由实际事件控制状态，无音素同步与音频导出。资料：[MDN](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis)。
VoiceSamples 存储原始音频与同意/来源文字，按场所隔离；校验大小、音频容器特征、名称、授权，不等于服务器已完整解码录音。真实解码、3–60秒长度与单声道处理由本地模型服务完成。目录 data/voice-samples 不提交。可试听原始样音并删除。
LocalTTSAdapter 只接受显式配置的本机HTTP端点，POST文字、性格、情绪、强度与参考音频及对应文字，返回真实音频字节；未配置返回503，失败无静默替代。实现不默认把样音发往外部服务。
预备 Qwen CPU 独立服务见 services/tts/qwen_server.py。0.6B Base 用于参考声音；该模型没有独立情绪指令能力，回执 X-TTS-Style-Control:not-supported。情绪可保存在角色设置，但不能宣称克隆音频已经按情绪控制。官方：[Qwen3-TTS](https://github.com/QwenLM/Qwen3-TTS)。安装与推理结果见验证记录。
