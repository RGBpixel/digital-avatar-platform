# 真人影像数字人试作（2026-10-19）

## 用户目标
使用本人或已授权真人影像作为数字人，保持现有多轮对话、声音、识人、昵称、记忆和提醒。显示自然嘴型、眨眼、微笑、头部与身体动作，可实时互动和打断。原八种二维角色保留，不将本阶段示意动画误称为真人视频驱动。

## 第一版范围
优先胸像或半身视频数字人：真人素材保持身份外观，以现有TTS音频驱动嘴型，待机/倾听/问候/告别使用预录制动作片段。微笑、眨眼、点头来自真人素材；任意情绪和自由身体动作不能宣称已经生成。全身显示及可控手势为后续扩展，不能以单张脸照承诺实现。

候选引擎先评估 MuseTalk 1.5（https://github.com/TMElyralab/MuseTalk），保留后续替换。官方实时数字是在指定GPU和预处理条件下报告，Windows 5070与现有TTS并发必须单独测试。LivePortrait（https://github.com/KlingAIResearch/LivePortrait）可作头姿/表情驱动候选，但不是直接替代音频嘴型或全身动作系统。

## 素材
由用户提供本人或明确授权的视频素材，不从真人档案库、人脸登记照片、公众人物照片中自行选人。建议1080p、25或30帧、固定机位、光线均匀、无遮挡、背景稳定。先准备30–60秒正面半身视频，包含放松待机、自然微笑、轻微点头；需要手势时另录挥手、介绍、告别，避免大幅侧脸。该时长是本项目首轮素材建议，不是模型硬性要求。一张照片可用于头部试验，不能验证身体动作。

## 隔离与接口
真人影像服务独立环境部署，不替换现有ASR/TTS环境。客户端通过可替换渲染适配器播放；每个音视频片段携带sessionId、replyId、sequence和时间戳，音频为主时钟。打断取消同replyId全部未播放画面与声音，旧回答画面不能回流。能力回执分别报告audioLipSync、headMotion、expression、bodyGesture和来源recorded/generated，不将预录动作说成实时生成。

## 本机资源与验收
读取nvidia-smi：RTX5070 Laptop，8151MiB，总使用约6422MiB（检查时瞬时值）。原本机2B视觉仍可能占显存，真人驱动启用前需确认当前视觉来源及进程，再决定按需卸载；不擅自关闭现有声音模型。先用单人单会话测试，再同时启用语音识别、现有声音、摄像头匹配。测量首音、首帧、稳定帧率、音画差、打断耗时、峰值显存，结果作为事实记录，不以官方帧率替代本机验收。
